# Handoff 交接文档 — 2026-08-05

## 任务背景

修复 A2UI 表单提交后的三个问题：
1. 提交时新开流式气泡（骨架屏"等待效果"）
2. 结果状态文本显示 LLM 的思维过程而非有意义的结果
3. 最终创建状态 A2UI 结果卡片独立新开气泡，而非在原表单气泡内渲染

## 已完成的修改

**问题2&3** — 核心后端修改。

当 `action_name` 存在（表单提交场景）时：
- `a2ui_jsonl` 结果存到 `a2ui_action` 用户消息的 `a2ui_jsonl` 字段，**不再创建独立 assistant 消息**

### 3. `frontend/src/views/ChatView.vue`

三处修改：

- **`handleA2UIAction`**：有 A2UI 结果时使用 `"操作完成"` 替代 LLM 思维文本作为 `action_result`（**问题2**）
- **`handleA2UIAction`**：A2UI 结果 JSONL 追加到原表单消息 `a2ui_jsonl`，不再创建独立新消息（**问题3**）

## 关键设计决策

### 为什么将结果 JSONL 追加到原消息的 a2ui_jsonl 而非新建字段？

`ChatMessage.vue` 中：
```ts
const a2uiRawText = computed(() => props.message.a2ui_jsonl || props.message.content || "");
const contentHash = computed(() => { /* 基于 a2uiRawText 的 hash */ });
```

`A2UIRenderer` 以 `contentHash` 为 key。当 `a2ui_jsonl` 变化（追加结果 JSONL），key 变化 → 组件重挂载 → 完整解析表单 JSONL + 结果 JSONL → 同一气泡内渲染表单和结果卡片。

重渲染副作用：表单字段回到 `updateDataModel` 初始状态（不显示用户填入值）。可接受，因为表单此时是 readonly。

### action_result 的清理逻辑

- 有 A2UI 结果卡片（`a2ui_jsonl` 存在）→ 用简短状态文本（"操作完成"/"操作失败"）
- 无 A2UI 结果卡片但有文本 → 用 `_extract_summary()` 提取摘要
- 两者都没有 → 默认"操作完成"

这样避免了 LLM 内部推理（"我来处理创建联系人的请求..."）被展示给用户。

## 数据流示意（修复后）

```
用户提交表单
  → a2ui_action 消息写入 DB:
      action_name = "create_contact"
      action_status = "submitted"
      a2ui_jsonl = NULL
      action_result = NULL
  
  → LLM 处理完成:
      a2ui_action 消息被更新:
        action_status = "done" / "failed"
        action_result = "操作完成" / "操作失败"   ← 简短状态，非思维过程
        a2ui_jsonl = "{结果 card JSONL}"           ← 结果卡片存这里
  
  → 实时（前端 handleA2UIAction）:
      找到原始表单消息 (by messageId)
      追加结果 JSONL → 表单消息.a2ui_jsonl
      → contentHash 变化 → A2UIRenderer 重新渲染
      → 同一气泡内显示表单 + 结果卡片 + action_result 横幅
  
  → 历史加载（loadHistory）:
      a2ui_action 消息被跳过（不显示）
      a2ui_action 的 a2ui_jsonl 追加到前一表单消息
      → 效果同上
```

## 待观察 / 潜在风险

1. **重渲染表单状态丢失**：追加结果 JSONL 后 A2UIRenderer 重挂载，表单回到初始化状态（不显示用户填入的值）。目前可接受（表单 readonly），但若未来改为可编辑模式需要重新考虑方案。

2. **LLM 成功场景**：当前成功时 `action_result` = "操作完成"。如果 LLM 输出了类似"已创建联系人 张三"的有意义文本（且没有 JSONL），会被保留。但如果 LLM 输出思维过程 + 无 JSONL 结果，action_result 可能仍包含噪音——目前依赖 `_extract_summary` 处理。

3. **多个 A2UI surface 同时存在**：表单 Surface 和结果 Surface 通过不同的 `surfaceId` 区分。A2UIRenderer 的 `buildSurfaces` 会分别构建它们，渲染为两个相邻的卡片。

## 下一步建议

- 在真实环境中验证三种场景：成功创建、创建失败（错误卡片）、历史刷新
- 如有必要，可以让 LLM 专门输出一个 `result_summary` 字段来精确控制 action_result 文本
