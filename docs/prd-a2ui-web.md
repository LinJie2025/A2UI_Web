# A2UI 独立 Web 应用 — 产品需求文档 (PRD)

---

## 1. 项目信息

| 字段 | 内容 |
|------|------|
| **语言** | 中文 |
| **编程语言 / 技术栈** | 前端：Vue 3 + Vite ｜ 后端：FastAPI (Python) ｜ 网关：Nginx |
| **项目名称** | `a2ui_web` |
| **原始需求复述** | 将当前以 Odoo 模块形式运行的 A2UI（智能聊天助手）拆分为独立 Web 应用。新应用自管用户认证、聊天历史与 Agentic Loop，通过 Odoo 官方 `/mcp` 端点（`tools/list` + `tools/call`，Bearer Token 鉴权）对接已部署的企业版 Odoo，LLM 推理由 A2UI 直连外部 API（DeepSeek / OpenAI）完成。 |

---

## 2. 产品定义

### 2.1 Product Goals

1. **独立的智能 ERP 对话入口**：用户无需登录 Odoo 即可通过 A2UI Web 与 ERP 系统进行自然语言交互，查询业务数据、执行操作，获得即时智能响应。
2. **安全可控的多层权限体系**：通过「System Prompt 约束 → Tool 白名单 → Tool 按 group 过滤 → Odoo ACL」四道防线，确保每个操作员只能访问其被授权的数据和工具。
3. **开放可扩展的 LLM 与工具架构**：LLM 引擎可灵活切换 DeepSeek / OpenAI 等外部模型；Tool 定义由 Odoo `/mcp` 端点动态注入 System Prompt，业务语义随 Tool 元数据自动同步，无需硬编码。

### 2.2 User Stories

| # | 用户故事 | 优先级 |
|---|----------|--------|
| 1 | As a **仓库管理员**, I want 在聊天框中输入「查库存少于 10 的产品」, so that 我能快速识别需要补货的商品，无需记忆 Odoo 菜单路径。 | P0 |
| 2 | As a **A2UI 管理员**, I want 在管理后台为每个操作员配置独立的 Odoo API Key 并勾选可用 Tool, so that 我能细粒度控制谁可以调用哪些 Odoo 功能。 | P0 |
| 3 | As a **销售经理**, I want 在对话中直接询问「本月销售额 Top 10 客户」并看到图表, so that 我能快速掌握业绩情况，无需导出报表。 | P1 |
| 4 | As a **普通操作员**, I want 系统记住我的历史对话, so that 我可以回溯之前的查询和分析结果，避免重复提问。 | P1 |
| 5 | As a **IT 运维**, I want A2UI 启动时自动从 Odoo `/mcp` 拉取最新 Tool 定义, so that Odoo 端新增模块或工具后 A2UI 无需人工维护 Tool 清单。 | P2 |

## 3. 技术规范

### 3.1 Requirements Pool

#### P0 — 必须交付（MVP）

| ID | 需求 | 说明 |
|----|------|------|
| P0-1 | **用户认证系统** | A2UI 自管用户名 + 密码，支持注册 / 登录 / 登出。管理员在后台为每个用户配置对应的 Odoo Bearer Token（API Key）。 |
| P0-2 | **聊天核心功能** | 单轮 + 多轮对话支持，消息输入框 + 发送按钮，SSE 流式接收 LLM 响应并实时渲染。 |
| P0-3 | **MCP 客户端集成** | 实现 `tools/list`（启动时拉取）与 `tools/call`（Agentic Loop 中调用）的 JSONRPC 2.0 通信，Bearer Token 鉴权。 |
| P0-4 | **Agentic Loop 自实现** | 循环逻辑：LLM 返回 tool_calls → MCP 执行 → 结果回填 → 继续推理，MAX_LOOPS=20，超时保护。 |
| P0-5 | **LLM 客户端** | 通过 openai SDK 连接 DeepSeek / OpenAI，支持 System Prompt 动态注入 Tool 列表，支持 tool_calls 模式。 |
| P0-6 | **System Prompt 构建** | 启动时调用 `tools/list` 获取 Tool 定义，按用户 groups 裁剪后注入 System Prompt（防线 1+3）。 |
| P0-7 | **FastAPI SSE 流式输出** | `/api/chat` 端点以 `StreamingResponse` + 标准 SSE 格式推送 LLM 增量输出。 |

#### P1 — 应该交付

| ID | 需求 | 说明 |
|----|------|------|
| P1-1 | **管理后台 — 用户管理** | 管理员可创建 / 编辑 / 禁用操作员账号，配置每人对应的 Odoo API Key 与所属角色。 |
| P1-2 | **管理后台 — 角色与 Tool 白名单** | 按角色勾选可用 Tool 列表（防线 2），角色可分配给多个用户。 |
| P1-3 | **聊天历史存储** | SQLite 存储全部对话，支持历史会话列表、点击回溯、删除会话。 |
| P1-4 | **A2UI JSONL 渲染器** | 前端解析 LLM 输出的 A2UI JSONL 格式，渲染为富交互 UI 组件（卡片、表格、图表等）。 |
| P1-5 | **四道防线联动测试** | 端到端验证：低权限用户 → System Prompt 不含敏感 Tool → 白名单拒绝 → groups 过滤 → Odoo ACL 最终拦截。 |

#### P2 — 可以延后

| ID | 需求 | 说明 |
|----|------|------|
| P2-1 | **LLM 引擎热切换 UI** | 管理后台支持在 DeepSeek / OpenAI 间切换，配置各自的 API Key 和 Base URL。 |
| P2-2 | **多 Odoo 实例支持** | 一个 A2UI 实例同时对接多个 Odoo 后端，按用户配置指向不同 Odoo。 |
| P2-3 | **会话导出** | 支持将对话导出为 Markdown / PDF。 |
| P2-4 | **使用量统计面板** | LLM Token 消耗 + MCP 调用次数统计，按用户 / 按时间维度展示。 |

### 3.2 UI Design Draft

#### 主界面布局（聊天页）

```
┌──────────────────────────────────────────────────┐
│  A2UI                                    [头像]   │  ← 顶部导航栏
├──────────┬───────────────────────────────────────┤
│          │                                       │
│ 会话列表  │         【聊天消息区域】                │
│          │  用户：查库存少于10的产品                │
│  ├ 会话1  │  AI：正在调用 tool: product_search...  │
│  ├ 会话2  │  AI：[渲染结果卡片 / 表格]              │
│  ├ 会话3  │                                       │
│          │                                       │
│ [+新会话] │                                       │
│          ├───────────────────────────────────────┤
│          │  [输入框...........................] [发送] │  ← 底部输入区
└──────────┴───────────────────────────────────────┘
```

- **顶部导航栏**：Logo + 应用名，右侧用户头像下拉菜单（设置 / 退出）
- **左侧会话列表**（P1）：历史会话列表，点击切换，顶部「新建会话」按钮
- **聊天消息区域**：用户消息右对齐气泡，AI 消息左对齐，流式输出逐字渲染，A2UI JSONL 组件嵌入式渲染
- **底部输入区**：文本输入框 + 发送按钮，Enter 发送

#### 管理后台布局

```
┌──────────────────────────────────────────────────┐
│  A2UI 管理后台                                    │
├──────────┬───────────────────────────────────────┤
│  导航     │                                       │
│  ├ 用户管理│     [用户列表 / 创建 / 编辑面板]        │
│  ├ 角色管理│                                       │
│  └ 系统设置│                                       │
└──────────┴───────────────────────────────────────┘
```

- **用户管理**：表格展示用户列表（用户名、角色、Odoo API Key 掩码、状态），支持新建 / 编辑 / 禁用
- **角色管理**：角色列表，每个角色可勾选 MCP Tool 白名单
- **系统设置**（P2）：LLM 引擎配置、Odoo 实例连接配置

### 3.3 Open Questions（待确认事项）

| # | 问题 | 影响范围 | 建议 |
|---|------|---------|------|
| Q1 | **A2UI 前端 UI 设计风格**：先用基础样式快速验证，还是直接做完整 UI 设计稿？ | 前端开发排期 | 建议 MVP 阶段使用基础样式 + 组件库（如 Element Plus / Naive UI）快速出活，P1 再做视觉升级。 |
| Q2 | **管理后台的具体功能范围**：除用户管理 + 角色配置 + 会话查看外，是否需要日志审计、Token 用量统计、告警通知？ | 后端 API 设计 | 建议 MVP 仅用户管理 + 角色配置，P2 扩展统计和审计功能。 |
| Q3 | **A2UI JSONL 渲染器是否需要从 ES5 重写为 ES6**？ | 前端架构 | 建议统一为 ES6 + TypeScript，与 Vue 3 技术栈一致，避免后期维护两套语法。 |
| Q4 | **数据库选型**：SQLite 是否满足并发需求？预估用户量级？ | 后端架构 | SQLite 适合单机 ≤50 并发用户，若预期超此规模需评估 PostgreSQL。 |
| Q5 | **Odoo `/mcp` 端点版本兼容性**：目标 Odoo 版本范围？`tools/list` 返回的 Tool 数量预估？ | MCP 客户端设计 | 建议明确支持的 Odoo 最低版本（如 17.0+），评估 Tool 列表大小以确定 System Prompt token 预算。 |
| Q6 | **部署模式**：Docker 容器化 vs 裸机部署？是否需要提供 Docker Compose 一键部署方案？ | DevOps | 建议提供 Docker Compose 方案，降低运维门槛。 |

## 4. 非功能性需求

| 类别 | 要求 |
|------|------|
| **性能** | 首条 SSE 事件延迟 ≤2s（不含 LLM 推理）；Agentic Loop 每轮 ≤30s 超时 |
| **安全** | 密码 bcrypt 哈希存储；API Key AES-256 加密存储；HTTPS 传输 |
| **可用性** | 单点部署，SQLite 定期备份；LLM API 故障时前端友好提示 |
| **可维护性** | 前后端分离，Docker 化部署；Tool 定义零硬编码，动态同步 |
